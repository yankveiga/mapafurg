EXPLICACAO RAPIDA - COMO ALTERAR DADOS DO MAPA FURG

========================================================================
1) COMO ADICIONAR UM NOVO PREDIO
========================================================================

Arquivo principal:
- src/data/predios.js

Passo 1: criar um novo objeto dentro do array predios

Modelo basico:

{
  id: "novo_predio",
  nome: "Nome do Novo Predio",
  lat: -32.000000,
  lng: -52.000000,
  descricao: "Descricao curta do local.",
  aliases: ["apelido", "outro nome"]
}

Campos principais:

- id:
  identificador unico do ponto.
  Use letras minusculas, sem acento e sem espaco.
  Exemplo: "pavilhao_7", "laboratorio_x", "novo_predio".

- nome:
  nome que aparece no painel do mapa.

- lat e lng:
  coordenadas do ponto no mapa.

- descricao:
  texto exibido quando o usuario abre o painel do predio.

- aliases:
  nomes alternativos usados pela busca.
  Exemplo: se o predio e conhecido por uma sigla ou apelido, coloque aqui.

Passo 2: adicionar informacoes opcionais, se existirem

Projetos/laboratorios:

projetos: [
  {
    sigla: "PET C3",
    nome: "PET Ciencias Computacionais",
    sala: "Sala 114",
    link: "https://exemplo.com"
  }
]

Horario de funcionamento:

horarios: {
  "segunda a sexta": "08:00 - 18:00",
  "sabado": "fechado"
}

Cardapio:

cardapio: {
  "segunda": "Arroz, feijao e prato principal",
  "terca": "..."
}

Horarios do onibus interno:

interno: {
  "manha": "07:45, 08:30, 09:15",
  "tarde": "13:30, 14:15, 15:00"
}

Passo 3: ajustar a busca, se necessario

Arquivo:
- src/utils/buscas.js

Se o novo predio precisar responder a termos especiais, adicione os apelidos
em src/utils/buscas.js apontando para o mesmo id usado em src/data/predios.js.

Exemplo:

"apelido do predio": ["novo_predio"]

Quando precisa mexer em src/utils/buscas.js?

- quando o usuario pode procurar por um nome que nao esta em nome ou aliases;
- quando existe uma regra especial;
- quando uma sala ou apelido deve levar diretamente ao predio.

Passo 4: testar

Rode:

npm.cmd run dev

Depois procure pelo nome, id e aliases na barra de busca.

========================================================================
2) COMO ADICIONAR UM NOVO ONIBUS RASTREADO
========================================================================

Arquivos principais:
- src/data/onibus.js
- public/
- app rastreador externo
- server/ws-server.js, se for mudar a regra de busId

Importante:
- o ponto informativo "Onibus Interno - FURG" continua em src/data/predios.js;
- os onibus rastreados em tempo real ficam configurados em src/data/onibus.js.

Hoje ja existe uma estrutura para:

- onibus_amarelo
- interno_branco
- onibus_teste

Passo 1: cadastrar o onibus em src/data/onibus.js

Exemplo:

export const ONIBUS_CONFIG = {
  onibus_amarelo: {
    nome: 'Interno Amarelo',
    icone: '/map-icons/interno.svg',
    acessivel: true,
  },
  interno_branco: {
    nome: 'Interno Branco',
    icone: '/map-icons/interno_branco.svg',
    acessivel: false,
  },
  onibus_teste: {
    nome: 'Onibus Teste',
    icone: '/map-icons/interno.svg',
    acessivel: false,
    teste: true,
  },
};

Campos:

- chave do objeto:
  deve ser igual ao busId enviado pelo app rastreador.
  Exemplo: onibus_amarelo.

- nome:
  nome humano do onibus.

- icone:
  caminho do SVG dentro da pasta public/.
  Exemplo: /map-icons/interno-amarelo.svg.

- acessivel:
  true para onibus com acessibilidade;
  false para onibus sem acessibilidade;
  null quando nao se sabe.

- teste:
  true quando for um rastreador usado apenas para teste.

Passo 2: colocar o icone em public/

Exemplo:

public/
  interno-amarelo.svg
  interno-branco.svg
  interno-teste.svg

Depois, em src/data/onibus.js:

onibus_amarelo: {
  nome: 'Interno Amarelo',
  icone: '/map-icons/interno-amarelo.svg',
  acessivel: true,
}

Passo 3: configurar o app rastreador

O app externo precisa enviar o mesmo busId:

{
  "type": "bus_location",
  "busId": "onibus_amarelo",
  "lat": -32.074,
  "lng": -52.167,
  "timestamp": "2026-06-21T12:00:00.000Z"
}

Para melhorar a qualidade da movimentacao, tambem pode enviar:

{
  "speed": 8.7,
  "accuracy": 6.2
}

Termos:

- speed (velocidade):
  velocidade estimada pelo GPS.

- accuracy (precisao):
  margem de erro estimada pelo GPS, em metros.

Passo 4: regra do servidor

Atualmente, o servidor pode atribuir ids automaticos como:

- bus-1
- bus-2

Isso permite que apps antigos continuem funcionando.

O servidor tambem aceita ids especificos como onibus_amarelo. A regra usada e:

Se o app mandou busId valido:
  usar esse busId.
Senao:
  manter o comportamento antigo e usar id automatico/generico.

Assim, o sistema fica compativel com:

- app antigo sem busId especifico;
- app novo com onibus_amarelo;
- app novo com interno_branco;
- app de teste com onibus_teste.

Passo 5: testar no mapa

Com o servidor e frontend rodando:

npm.cmd run dev:all

Envie uma mensagem pelo app rastreador ou pelo public/ws-tester.html.

Se o busId for cadastrado em src/data/onibus.js, o mapa usa a configuracao dele.
Se o busId nao for cadastrado, o mapa usa ONIBUS_PADRAO.

========================================================================
3) RESUMO RAPIDO
========================================================================

Para predio novo:

1. Adicionar objeto em src/data/predios.js.
2. Colocar aliases se necessario.
3. Ajustar src/utils/buscas.js apenas se precisar de busca especial.
4. Testar no mapa.

Para onibus novo:

1. Adicionar configuracao em src/data/onibus.js.
2. Colocar SVG em public/.
3. Fazer o app rastreador enviar o mesmo busId.
4. Garantir que o servidor aceite esse busId.
5. Testar no mapa.

========================================================================
4) MOVIMENTO E OPACIDADE DO ONIBUS ATUAL
========================================================================

Arquivos principais:
- src/services/busTracking.js
- src/components/map/BusMarker.jsx
- src/hooks/useBusLocations.js
- src/App.jsx

Como funciona:
- o app rastreador envia apenas posicoes reais via WebSocket;
- o frontend recebe a coordenada real e calcula uma interpolacao visual;
- nenhuma posicao interpolada e enviada ao servidor;
- a frequencia do rastreador nao e alterada.

Intervalo usado como referencia:
- o rastreador envia localizacao a cada 3 segundos;
- a animacao visual usa o intervalo entre timestamps recebidos;
- os limites atuais ficam entre 900 ms e 2200 ms.

Quando chega uma nova posicao durante uma animacao:
- BusMarker cancela a animacao anterior;
- le a posicao visual atual do marcador no Leaflet;
- inicia uma nova animacao dali ate a nova coordenada real.

Quando as atualizacoes param:
- o marcador nao continua andando sozinho;
- ele permanece na ultima posicao real conhecida;
- a opacidade diminui conforme essa posicao envelhece.

Limites de opacidade:
- ate 10 segundos: 100%;
- de 10 a 30 segundos: cai gradualmente ate cerca de 70%;
- de 30 a 60 segundos: cai gradualmente ate cerca de 30%;
- acima de 60 segundos: permanece visivel com cerca de 30%.

Quando o servidor envia bus_disconnected:
- useBusLocations preserva a ultima posicao real;
- marca disconnectedAt;
- App.jsx mostra o status como Offline quando so restou uma posicao antiga;
- o marcador continua visivel, mas transparente.

Para ajustar esses valores, altere BUS_TRACKING_CONFIG em:

src/services/busTracking.js

Evite criar regras paralelas em outros arquivos para nao gerar conflito entre
status, movimento e opacidade.
